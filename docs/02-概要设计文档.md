# 智慧校园健康管理系统概要设计文档
## Software Architecture Design (SAD)

— 面向世界五百强交付标准 —

文档版本: v2.0.0  
状态: 正式发布  
适用范围: 架构师、资深开发、测试、运维

---

## 1. 设计目标与原则

- 可用性: 年可用≥99.5%, 关键服务可降级、自动恢复
- 可扩展性: 模块解耦, 支持水平扩展、读写分离、缓存前置
- 安全性: 全链路HTTPS、RBAC与细粒度鉴权、敏感信息加密
- 可观测性: 统一日志、指标、追踪三大支柱, 快速定位问题
- 可维护性: 统一接口规范、统一错误码、充足注释与文档

---

## 2. 总体架构（4+1视图）

### 2.1 逻辑视图（分层与模块）

- 表现层: Vue3/Element Plus 前端应用
- 接入层: Spring Web MVC + OpenAPI 文档
- 业务层: 人员管理、健康监测、医疗服务、订单支付、通知、系统管理
- 数据访问层: MyBatis-Plus Mapper/ServiceImpl
- 基础设施层: MySQL、Redis、阿里云短信、支付宝、OpenAI、Druid连接池

模块划分与职责:
- personnel: 学生/教师/家长/后勤/校医管理
- health: 健康数据采集、查询、预警、AI建议
- medical: 药品、医院、预约、库存预警
- order: 药品订单、员工订单、物流
- notification: 系统公告、预警通知、短信
- system: 认证授权、日志审计、统计、配置

### 2.2 进程视图（并发与交互）

- Web请求线程池: 处理HTTP请求
- Redis连接池: 缓存与会话读写
- 数据库连接池: Druid, 最大并发200
- 第三方调用: OpenAI/支付宝/短信, 使用超时与重试策略

### 2.3 开发视图（代码结构）

后端包结构（com.smart.www）:
- config: 跨域、Swagger、MyBatis-Plus、Redis、WebMvc
- controller: REST端点
- service + service.impl: 业务接口与实现
- mapper: MyBatis-Plus Mapper接口
- pojo: 实体、DTO、VO、Query
- util: 工具类(Result、加密、JWT、Redis封装)
- interceptor, exception: 拦截与异常

前端目录（src）:
- api, router, store, views, components, utils, styles, assets

### 2.4 物理/部署视图（环境与拓扑）

最小生产拓扑:
- Nginx(可选) → SpringBoot应用 × 2（无状态）
- MySQL 主从（读写分离可选）
- Redis 单机/哨兵
- 外部: 支付宝、OpenAI、阿里云短信

网络:
- 北向HTTPS, 南向出网白名单, 防火墙开放80/443/8081

### 2.5 场景视图（关键用例时序）

1) 健康数据上报: 设备→API→校验→入库→预警→通知
2) 下单支付: 前端下单→创建订单→支付宝支付→回调→更新订单→扣减库存→通知
3) 预警闭环: 触发预警→多方通知→处理反馈→状态流转→统计分析

## 3. 技术选型与取舍

- Spring Boot 3: 生态成熟、云原生友好
- MyBatis-Plus: 快速CRUD、分页插件、低学习成本
- Redis: 热数据缓存、会话、限流支撑
- SpringDoc: 自动API文档, 降低前后端沟通成本
- Sa-Token: 简洁易用的认证授权
- Druid: 稳定的连接池与内置监控
- OpenAI/支付宝/阿里云: 业务所需的外部能力

取舍说明:
- 单体分层而非微服务: 当前规模更适配, 降低运维复杂度; 保留将来拆分空间
- MySQL单库: 初始阶段足够, 预留读写分离与分库分表演进

## 4. 跨领域设计（Cross-cutting Concerns）

### 4.1 安全
- 认证: Sa-Token + JWT, Token 30天有效, 支持并发登录
- 授权: RBAC按角色+资源路由, 控制器注解校验
- 传输: 全站HTTPS, HSTS, TLS1.2+
- 数据: 密码MD5+Salt, 敏感配置外部化; 防SQL注入/XSS/CSRF

### 4.2 配置
- application.yaml + profiles（dev）
- 统一配置项: 端口、DB、Redis、Sa-Token、Swagger
- 敏感配置: 环境变量/密钥管理服务

### 4.3 缓存
- 缓存策略: 热点列表/统计结果, TTL+主动失效
- 防击穿: 缓存空值; 防雪崩: 随机过期; 防穿透: 参数校验+限流

### 4.4 事务与一致性
- 事务边界: Service层, 订单与库存扣减同事务
- 一致性: 本地事务优先; 外部回调（支付）幂等保障

### 4.5 日志与观测
- 统一日志格式: traceId、spanId、userId、uri、rt、code
- 访问日志与审计日志分流; 预警/支付关键路径打点
- 监控指标: QPS、RT、错误率、线程/连接池、GC、堆使用

## 5. 关键数据流与时序

### 5.1 健康上报时序
1) 设备发起上传(JSON)  
2) 网关验签(可选)  
3) 控制器参数校验→Service→Mapper入库  
4) 异常检测→生成预警→写通知  
5) 返回上报结果

### 5.2 支付时序
1) 创建订单(预占库存)  
2) 生成支付表单并跳转支付宝  
3) 支付回调验签  
4) 更新订单状态→扣减库存→记录流水  
5) 通知后勤→发货

---

## 6. 接口规范与错误码

- 统一响应: Result<T> = { code, message, data }
- 错误码: 200成功; 400参数错误; 401未认证; 403无权限; 404未找到; 429限流; 500服务异常
- 幂等性: 回调接口、重复提交通过业务键+去重表控制

---

## 7. 部署与容量规划

- 单实例: 2C4G可支撑QPS 300~500（参考场景）
- 生产建议: 2实例 × 4C8G, MySQL 4C8G, Redis 2C4G
- 连接池: DB max 200, Redis max 100
- 备份: DB全量每日, 增量每小时, 保留30天

---

## 8. 演进路线

- 阶段1: 单体分层 + 缓存前置 + 读写分离
- 阶段2: 拆分健康/订单/通知为独立服务, 引入消息队列
- 阶段3: 上云与弹性伸缩, 引入服务网格, 完善可观测性

---

## 9. 风险与对策

- 外部依赖不稳定: 超时/重试/熔断/降级
- 数据增长: 分库分表、冷热数据分层、归档
- 安全合规: 等保测评流程, 敏感数据加密与脱敏

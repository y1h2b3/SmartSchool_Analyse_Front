## 1. 数据库概述

### 1.1 设计原则

**规范化与反规范化平衡:**
- 核心实体表遵循第三范式（3NF）
- 为提升查询性能，允许适度冗余（如img字段存储LONGBLOB）
- 不使用物理外键约束，采用逻辑外键保持灵活性

**性能优先:**
- 高频查询字段建立索引
- 大字段（img）存储二进制数据，避免单独的文件服务
- 时间字段统一使用DATETIME类型

**可扩展性:**
- user_health表预留24小时心率字段（1hour_avg_heart_rate ~ 24hour_avg_heart_rate）
- user_health表预留时段步数字段（0-6step, 6-12step, 12-18step, 18-24step）

**安全性:**
- 密码字段使用加密存储（不可逆）
- 操作日志完整记录（logs_data表）
- 删除采用软删除（status字段）

### 1.2 命名规范

- **表名**: 小写+下划线，如 `student`, `user_health`
- **字段名**: 小写+下划线，如 `student_id`, `create_time`
- **主键**: 统一命名为 `id`（BIGINT AUTO_INCREMENT）
- **时间字段**: `create_time`, `update_time`
- **状态字段**: `status`（INT类型，1正常/0停用）

## 3. 核心表详细设计

### 3.1 student（学生表）

**用途:** 存储学生基本信息、关联信息及账号凭证

**表结构:**
```sql
CREATE TABLE `student` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT,
  `img` longblob NOT NULL COMMENT '图片（头像，二进制存储）',
  `type` varchar(32) NOT NULL COMMENT '人员类型（固定值"学生"）',
  `grade` varchar(32) NOT NULL COMMENT '年级（如"初一"、"高二"）',
  `device_id` varchar(32) NOT NULL COMMENT '设备ID（智能手环等）',
  `birth` date NOT NULL COMMENT '出生日期',
  `parent_id` varchar(255) NOT NULL COMMENT '家长ID（逻辑外键→parent.parent_id）',
  `student_id` varchar(255) NOT NULL COMMENT '学号（业务主键，唯一）',
  `teacher_id` varchar(255) NOT NULL COMMENT '班主任ID（逻辑外键→teacher.teacher_id）',
  `clazz` varchar(32) NOT NULL COMMENT '班级（如"1班"、"2班"）',
  `name` varchar(32) NOT NULL COMMENT '姓名',
  `password` varchar(64) NOT NULL COMMENT '密码（加密存储）',
  `phone` varchar(11) NOT NULL COMMENT '手机号（11位）',
  `sex` varchar(2) NOT NULL COMMENT '性别（男/女）',
  `status` int(11) NOT NULL COMMENT '账号状态（1正常/0离职/停用）',
  `create_time` datetime NOT NULL COMMENT '创建时间',
  `update_time` datetime NOT NULL COMMENT '最后修改时间',
  PRIMARY KEY (`id`) USING BTREE,
  INDEX `device_id`(`device_id` ASC) USING BTREE,
  INDEX `parent_id`(`parent_id` ASC) USING BTREE,
  INDEX `student_id`(`student_id` ASC) USING BTREE,
  INDEX `teacher_id`(`teacher_id` ASC) USING BTREE,
  INDEX `clazz`(`clazz` ASC) USING BTREE,
  INDEX `phone`(`phone` ASC) USING BTREE
) ENGINE = InnoDB AUTO_INCREMENT = 6501 
  CHARACTER SET = utf8mb4 
  COLLATE = utf8mb4_0900_ai_ci 
  ROW_FORMAT = DYNAMIC;
```

**字段说明:**

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| id | BIGINT(20) | √ | AUTO_INCREMENT | 主键 |
| img | LONGBLOB | √ | - | 头像图片（二进制） |
| type | VARCHAR(32) | √ | - | 固定为"学生" |
| grade | VARCHAR(32) | √ | - | 年级 |
| device_id | VARCHAR(32) | √ | - | 绑定的智能设备ID |
| birth | DATE | √ | - | 出生日期 |
| parent_id | VARCHAR(255) | √ | - | 关联家长 |
| student_id | VARCHAR(255) | √ | - | 学号（唯一标识） |
| teacher_id | VARCHAR(255) | √ | - | 班主任ID |
| clazz | VARCHAR(32) | √ | - | 班级名称 |
| name | VARCHAR(32) | √ | - | 学生姓名 |
| password | VARCHAR(64) | √ | - | 登录密码（MD5+Salt） |
| phone | VARCHAR(11) | √ | - | 手机号 |
| sex | VARCHAR(2) | √ | - | 性别 |
| status | INT(11) | √ | - | 1=正常，0=停用 |
| create_time | DATETIME | √ | - | 记录创建时间 |
| update_time | DATETIME | √ | - | 记录更新时间 |

**索引策略:**
- `PRIMARY KEY (id)`: 聚簇索引
- `INDEX device_id`: 设备ID查询
- `INDEX parent_id`: 家长关联查询
- `INDEX student_id`: 学号查询（高频）
- `INDEX teacher_id`: 班主任关联查询
- `INDEX clazz`: 班级筛选（列表页）
- `INDEX phone`: 手机号登录

**业务规则:**
1. student_id必须全局唯一
2. password采用不可逆加密
3. status=0时不删除记录，仅标记为停用
4. img字段存储二进制，前端需Base64编码

**当前数据量:** AUTO_INCREMENT = 6501

### 3.7 user_health（用户健康数据表）⭐核心表

**用途:** 存储所有用户的实时健康数据（学生、教师、后勤等）

**表结构:**
```sql
CREATE TABLE `user_health` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '主键',
  `user_id` varchar(255) DEFAULT NULL,
  
  -- 基础指标
  `height` decimal(5, 2) NOT NULL COMMENT '身高',
  `weight` decimal(5, 2) NOT NULL COMMENT '体重',
  `fat_percentage` decimal(5, 2) NOT NULL COMMENT '脂肪率',
  `BMI` decimal(5, 2) NOT NULL COMMENT 'BMI',
  `type` varchar(32) NOT NULL COMMENT '身体类型',
  `measure_time` varchar(32) NOT NULL COMMENT '最近测量时间',
  
  -- 睡眠数据

  `deep_sleep_total` varchar(32) NOT NULL COMMENT '累计深睡时长',
  `light_sleep_total` varchar(32) NOT NULL COMMENT '累计浅睡时长',
  `wake_time_total` varchar(32) NOT NULL COMMENT '累计清醒时长',
  `list_sleep_time` varchar(32) NOT NULL COMMENT '昨晚入睡时间',
  `today_wakeup_time` varchar(32) NOT NULL COMMENT '今天起床时间',
  
  -- 运动数据
  `step` varchar(32) NOT NULL COMMENT '走路步数',
  `walking_distance` varchar(32) NOT NULL COMMENT '走路距离',

  `18-24step` varchar(32) DEFAULT NULL,
  
  -- 24小时心率统计（扩展字段）
  `1hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `2hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `3hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `4hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `5hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `6hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `7hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `8hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `9hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `10hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `11hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `12hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `13hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `14hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `15hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `16hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `17hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `18hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `19hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `20hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `21hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `22hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `23hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  `24hour_avg_heart_rate` varchar(32) DEFAULT NULL,
  
  PRIMARY KEY (`id`) USING BTREE,
  INDEX `user_id`(`user_id` ASC) USING BTREE
) ENGINE = InnoDB AUTO_INCREMENT = 3301 
  CHARACTER SET = utf8mb4 
  COLLATE = utf8mb4_0900_ai_ci 
  ROW_FORMAT = DYNAMIC;
```

**字段详解:**

**基础指标:**
- `BMI`: 体重指数（计算公式: weight / (height/100)²）
- `type`: 体型分类（偏瘦/正常/偏胖/肥胖）

**睡眠数据:**
- 单位：小时（h）或分钟（min）
- list_sleep_time: 格式如"23:30"
- today_wakeup_time: 格式如"06:45"

**运动数据:**
- step: 当天累计步数
- walking_distance: 单位公里（km）
- calorie: 消耗卡路里（kcal）

**生命体征:**
- mean_resting_heart_rate: 平均心率（次/分）
- spo2: 血氧饱和度（正常值≥95%）
- temperature: 体温（正常值36.0-37.3°C）

**扩展字段用途:**
- `1hour_avg_heart_rate` ~ `24hour_avg_heart_rate`: 用于绘制24小时心率曲线图
- `0-6step` ~ `18-24step`: 用于分析不同时段的活动量

**业务规则:**
1. 每个user_id每天可能有多条记录（设备多次上报）
2. check_warning字段标记是否触发预警
3. 数据保留30天后归档至user_health_daily

**当前数据量:** AUTO_INCREMENT = 3301

  `BMI` decimal(5, 2) NOT NULL COMMENT 'BMI',
  `type` varchar(32) NOT NULL COMMENT '身体类型',

  INDEX `date`(`date` ASC) USING BTREE
) ENGINE = InnoDB AUTO_INCREMENT = 10001

  ROW_FORMAT = DYNAMIC;
```

**与user_health区别:**
- 增加`date`字段（按日期聚合）
- 每个用户每天只保留一条记录（取当天最后一次测量值或平均值）
- 索引增加`INDEX date`

**归档策略:**
- 定时任务（每日凌晨2:00）将user_health中30天前数据归档
- 归档后删除原始数据，释放空间

**当前数据量:** AUTO_INCREMENT = 10001

  `time` datetime NOT NULL COMMENT '预警发出的时间',
  `reading_value` varchar(255) NOT NULL COMMENT '测量值',
  `recommended_action` varchar(255) NOT NULL COMMENT '建议的行动或措施',
  `create_time` datetime NOT NULL COMMENT '创建时间',
  `update_time` datetime NOT NULL COMMENT '最后修改时间',
  `reading_key` varchar(255) DEFAULT NULL,
  PRIMARY KEY (`id`) USING BTREE,
  INDEX `notification_id`(`notification_id` ASC) USING BTREE,
  INDEX `time`(`time` ASC) USING BTREE
) ENGINE = InnoDB AUTO_INCREMENT = 50001 
  CHARACTER SET = utf8mb4 
  COLLATE = utf8mb4_0900_ai_ci 
  ROW_FORMAT = DYNAMIC;
```

**字段说明:**

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| notification_id | VARCHAR(32) | 预警通知唯一ID | "WARN20240525001" |
| user_id | VARCHAR(32) | 触发预警的用户ID | "2024001"（学号） |
| type | VARCHAR(255) | 预警类型 | "体温异常"/"心率异常"/"血氧异常" |
| level | VARCHAR(255) | 预警等级 | "低级"/"中级"/"高级" |
| time | DATETIME | 预警触发时间 | 2024-05-25 08:30:15 |
| reading_value | VARCHAR(255) | 异常测量值 | "体温: 38.5°C" |
| recommended_action | VARCHAR(255) | 建议措施 | "立即就医，通知家长" |
| reading_key | VARCHAR(255) | 预警字段标识 | "temperature"/"spo2" |

**预警类型枚举:**
- 体温异常（≥38.0°C 或 ≤35.5°C）
- 心率异常（>120次/分 或 <50次/分）
- 血氧异常（<90%）
- 体重异常（BMI过高或过低）
- 睡眠异常（<5小时/天）

**预警等级定义:**
- **低级**: 轻微异常，建议关注
- **中级**: 明显异常，需要干预
- **高级**: 严重异常，立即处理

**业务流程:**
1. user_health数据插入时触发预警检测
2. 匹配预警规则，生成预警记录
3. 发送通知（系统内通知+短信）
4. 校医或班主任查看并处理

**当前数据量:** AUTO_INCREMENT = 50001

mysqldump -u root -p --databases smart_campus \
  --single-transaction \

# 开启binlog

- user_health表（每小时增量备份）

### 8.2 恢复流程

**完全恢复（恢复到某个全量备份点）:**
```bash
mysql -u root -p smart_campus < /backup/smart_campus_full_20240525.sql
```

**时间点恢复（恢复到某个具体时间）:**
```bash
# 1. 恢复全量备份
mysql -u root -p smart_campus < /backup/smart_campus_full_20240525.sql

# 2. 应用增量binlog（恢复到指定时间点）
mysqlbinlog --stop-datetime="2024-05-25 14:30:00" \
  /backup/smart_campus_inc_20240525.sql | mysql -u root -p smart_campus
```
